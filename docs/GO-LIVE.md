# OrbitOS Go-Live Checklist

Last updated 2026-10-11. Do the steps in order; each produces values a later step needs.

## Before you start

Plan on about one working day of setup, plus IntaSend's KYC review, which can take a few days. You can go live on the 14-day trial while KYC finishes, because nobody pays until a trial ends.

| Account | Plan to pick | Why that plan |
| --- | --- | --- |
| [Supabase](https://supabase.com/dashboard) | Pro | Daily backups, no pausing when idle, custom SMTP |
| [Vercel](https://vercel.com) | Hobby to test, Pro once you charge customers | Vercel's terms limit Hobby to non-commercial use; hourly jobs run from GitHub Actions on either plan |
| [Resend](https://resend.com) | Free to start | Sends sign-up, reset, invite and digest emails |
| [IntaSend](https://intasend.com) | Business account, KYC done | M-Pesa and card payments for subscriptions and invoices |
| [Sentry](https://sentry.io) | Free (Developer) | Emails you when the app crashes |
| [Meta for Developers](https://developers.facebook.com) | WhatsApp Cloud API (optional) | Check-ins by reply, one-tap approvals, weekly brief on WhatsApp |
| [Anthropic Console](https://console.anthropic.com) | Pay as you go (optional) | Writes the AI chief-of-staff brief; a few cents per workspace a month |
| [KRA eTIMS](https://etims.kra.go.ke) | OSCU integration (optional) | Fiscal receipts and tax invoices; KRA must vet OrbitOS first, which takes time — start early |
| [Google Cloud](https://console.cloud.google.com) / [Microsoft Entra](https://entra.microsoft.com) | Free (optional) | Two-way calendar sync; Google verifies calendar apps, which can take weeks |
| A domain | Any registrar | You need DNS access for Vercel and Resend |

Keep a private note open to collect the values below; never paste secrets into chat or email.

- Supabase: project URL, anon key, service_role key, database password
- Resend: API key
- IntaSend: publishable key, secret key, webhook challenge string
- Sentry: DSN
- Meta (optional): WhatsApp token, phone number ID, app secret, and a verify token you make up
- Anthropic (optional): API key
- KRA (optional): PIN, branch ID, device serial, item classification code
- Google / Microsoft (optional): calendar client IDs and secrets
- Generated by you: `CRON_SECRET` (run `openssl rand -hex 32`) and `ENCRYPTION_KEY` (run `openssl rand -hex 32` — keep a copy; changing it later disconnects every eTIMS device and calendar)

## Step 1 — Supabase project

This step leaves you with an empty production database that has the full schema, security rules and storage buckets, and no demo data.

**Create the project**

1. In the Supabase dashboard, click **New project**. Pick the region closest to your users: **eu-central-1 (Frankfurt)** or **eu-west-2 (London)** both work well from Nairobi. Save the database password.
2. Upgrade the organization to **Pro** under Organization → Billing.
3. Go to Project Settings → API and copy the **Project URL**, the **anon public** key and the **service_role** key. The service_role key bypasses all security; it goes only into Vercel, never into the browser or a chat.

**Or, without installing anything: use the SQL Editor.** Open Supabase → **SQL Editor → New query**, paste the whole of `supabase/setup_all.sql`, and click **Run** once. Then paste `supabase/verify_setup.sql` and run it: every row should show `ok = true`. The setup file refuses to run twice, so a second click changes nothing.

**Already have OrbitOS in this project?** Don't run `setup_all.sql` again. Run the update files in order, each once:

1. `supabase/update_differentiators.sql`, if the project was set up before 9 October 2026 (WhatsApp, payouts, languages, AI briefs).
2. `supabase/update_etims_calendar.sql`, if it was set up before 11 October 2026 (KRA eTIMS and calendar sync).

Each file refuses to run twice or out of order, and changes nothing if it stops. Then run `verify_setup.sql` again: all 13 rows `ok = true`. (With the CLI, `npx supabase db push` applies only the new migrations.)

**Push the schema (from your computer, inside the OrbitOS folder)**

```bash
npm install
npx supabase login
npx supabase link --project-ref <your-project-ref>
npx supabase db push
```

`db push` applies the six files in `supabase/migrations/` in order. Check the result in Table Editor: you should see `organizations`, `memberships`, `tasks`, `invoices` and the rest, every one marked **RLS enabled**. Storage should show four buckets: `avatars`, `evidence`, `vault`, `exports`.

**Never run `supabase/seed.sql` against this project.** It creates 12 demo users who all share the public password `OrbitOS-demo-2026`. Do not use `supabase db reset --linked` either, because it wipes the database and runs the seed.

**Auth → URL Configuration**

| Setting | Value |
| --- | --- |
| Site URL | `https://app.yourdomain.com` |
| Redirect URLs | `https://app.yourdomain.com/auth/callback` |
| Redirect URLs (only if you use subdomain workspaces) | `https://*.yourdomain.com/auth/callback` |

Every sign-in, sign-up, password reset and invite link returns through `/auth/callback`. If this URL is missing, links send people to the Site URL and they appear not to be signed in.

**Auth → Providers**

- **Email:** keep enabled. Turn on **Confirm email**. Set **Minimum password length** to 10 to match the sign-up form.
- **Google (optional):** create an OAuth client in Google Cloud Console → APIs & Services → Credentials. Set the authorized redirect URI to `https://<project-ref>.supabase.co/auth/v1/callback`, then paste the client ID and secret into Supabase.
- **Azure / Microsoft Entra ID (optional):** register an app in Entra ID with the same callback URI, and add the `email` optional claim. Paste the client ID, the secret and the tenant URL into Supabase. The app already requests the `email` scope.
- **SAML SSO (Enterprise customers only):** needs the Supabase Pro plan plus the SSO add-on. Add each customer's identity provider with `npx supabase sso add --type saml --metadata-url <their-metadata-url> --domains theircompany.com`.

**Auth → Multi-Factor:** make sure **TOTP (App Authenticator)** is enabled. It is on by default. The Vault and the owner-only billing actions require it.

**Auth → Rate Limits:** after you set up custom SMTP in Step 2, raise **Rate limit for sending emails** from the default 30 per hour to at least 100 per hour, so a team-wide invite does not stall.

**Backups:** on Pro, daily backups are automatic, and Database → Backups lists them. Add **Point-in-Time Recovery** later if losing up to a day of data would hurt.

## Step 2 — Email (Resend)

This step makes every email come from your own domain at a real volume. Supabase's built-in mailer sends only a few emails per hour and only to your own team, so without this step new users never get their confirmation link.

1. In Resend, go to **Domains → Add domain** and use a subdomain such as `mail.yourdomain.com`.
2. Add the DNS records Resend shows (an MX record, a TXT record for SPF, and a TXT record for DKIM) at your registrar. Wait until all of them show **Verified**. This usually takes minutes but can take up to 24 hours.
3. Add a DMARC record: TXT on `_dmarc.yourdomain.com` with the value `v=DMARC1; p=none; rua=mailto:you@yourdomain.com`.
4. Go to **API Keys → Create** with **Sending access** only, and copy the key.
5. In Supabase, open **Project Settings → Authentication → SMTP Settings**, turn on **Enable custom SMTP**, and enter:

| Field | Value |
| --- | --- |
| Sender email | `noreply@mail.yourdomain.com` |
| Sender name | `OrbitOS` (or your product name) |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | your Resend API key |

The same API key goes into Vercel as `RESEND_API_KEY`. The app uses it for invites, digests, check-in reminders and receipts. Set `EMAIL_FROM` to the same verified address, for example `OrbitOS <noreply@mail.yourdomain.com>`.

To check it works, use **Auth → Users → Invite user** in Supabase to invite your own email. The email should arrive within a minute and not land in spam.

## Step 3 — Vercel

This step puts the app on your domain with every secret set and the five background jobs running.

1. Push the OrbitOS folder to a **private** GitHub repository.
2. In Vercel, click **Add New → Project** and import the repo. The framework is detected as Next.js; leave the build settings at their defaults.
3. Before the first deploy, open **Environment Variables** and add every row below for the **Production** environment.
4. Deploy, then go to **Settings → Domains** and add `app.yourdomain.com`. Create the CNAME record Vercel shows at your registrar.
5. Upgrade the team to **Pro** before you take paying customers (Hobby is for non-commercial use). The hourly jobs don't need Pro: they run from GitHub Actions (see Crons below).

**Environment variables**

| Variable | Value | Required |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL | Yes |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key | Yes |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service_role key | Yes |
| `NEXT_PUBLIC_APP_URL` | `https://app.yourdomain.com` (no trailing slash) | Yes |
| `CRON_SECRET` | output of `openssl rand -hex 32` | Yes |
| `RESEND_API_KEY` | Resend key from Step 2 | Yes |
| `EMAIL_FROM` | `OrbitOS <noreply@mail.yourdomain.com>` | Yes |
| `INTASEND_PUBLISHABLE_KEY` | from Step 5 | Yes |
| `INTASEND_SECRET_KEY` | from Step 5 | Yes |
| `INTASEND_WEBHOOK_CHALLENGE` | a random string you choose (`openssl rand -hex 16`) | Yes |
| `INTASEND_TEST_MODE` | `true` until your sandbox payment works, then `false` | Yes |
| `INTASEND_CARD_CURRENCIES` | `KES,USD,EUR,GBP`, minus any currency your IntaSend account can't take by card (Step 5) | Optional (defaults to all four) |
| `WEBAUTHN_RP_ID` | `app.yourdomain.com` (just the host, no `https://`) | Yes, for passkeys |
| `WEBAUTHN_RP_NAME` | `OrbitOS` | Yes, for passkeys |
| `NEXT_PUBLIC_SENTRY_DSN` | Sentry DSN from Step 4 | Strongly recommended |
| `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT` | from Step 4 (gives readable stack traces) | Optional |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | a free Upstash Redis database | Recommended: makes login rate limits hold across all servers |
| `NEXT_PUBLIC_DATA_REGION` | e.g. `EU (Frankfurt)`, matching your Supabase region | Optional, display only |
| `NEXT_PUBLIC_ROOT_DOMAIN` | `yourdomain.com`, only if you want `acme.yourdomain.com` workspaces | Optional |
| `GITHUB_WEBHOOK_SECRET` | only if you use the GitHub integration | Optional |
| `ENCRYPTION_KEY` | output of `openssl rand -hex 32`; never change it afterwards | Yes, for eTIMS and calendar sync |
| `ETIMS_ENV`, `ETIMS_TIN`, `ETIMS_BHF_ID`, `ETIMS_DEVICE_SERIAL`, `ETIMS_ITEM_CLS_CD` | from KRA — see [`docs/ETIMS.md`](ETIMS.md) | Optional (fiscal receipts for plan payments) |
| `GOOGLE_CALENDAR_CLIENT_ID`, `GOOGLE_CALENDAR_CLIENT_SECRET` | see [`docs/CALENDAR.md`](CALENDAR.md) | Optional |
| `MICROSOFT_CALENDAR_CLIENT_ID`, `MICROSOFT_CALENDAR_CLIENT_SECRET` | see [`docs/CALENDAR.md`](CALENDAR.md) | Optional |

Never set `INTASEND_BASE_URL` in production. It exists only for the local test mock. After changing any `NEXT_PUBLIC_` variable, redeploy, because those values are baked in at build time.

**Put the app next to the database (biggest speed setting).** Vercel runs the app in Washington, D.C. (`iad1`) unless you change it, while your Supabase project is in Europe. Every page then waits for several trips across the Atlantic. In Vercel → your project → **Settings → Functions → Function Regions**, pick the region of your Supabase project: **Frankfurt (`fra1`)** for eu-central-1, **London (`lhr1`)** for eu-west-2. Redeploy. Pages typically load several hundred milliseconds faster after this.

**Optional, also faster: Supabase JWT signing keys.** In Supabase → **Project Settings → JWT Keys**, if the project still uses the legacy JWT secret, click **Migrate JWT secret**, then **Rotate keys**. OrbitOS then checks sign-ins locally instead of asking Supabase Auth on every page. Nobody is signed out. Leave the old secret in place for at least 1 hour 15 minutes before you revoke it, or skip revoking entirely.

**Passkeys are tied to the domain.** A passkey made on `app.yourdomain.com` will not work if you later move to another domain. Choose the final domain before users register passkeys.

**Crons**

Vercel's Hobby plan only allows daily crons, so the jobs are split. `vercel.json` runs the two daily jobs (check **Settings → Cron Jobs** lists `health-snapshot` and `retention`; Vercel sends `CRON_SECRET` automatically). The hourly jobs run from `.github/workflows/hourly-jobs.yml`, free on GitHub, one after another at about :07 each hour:

1. In GitHub, open the repo → **Settings → Secrets and variables → Actions → New repository secret**, and add `ORBITOS_URL` (your live address, no trailing slash) and `CRON_SECRET` (the same value as in Vercel).
2. Open the **Actions** tab → **Hourly jobs** → **Run workflow**. The run should go green and log `HTTP 200` for each job.
3. After that it runs by itself every hour. GitHub sometimes starts it a few minutes late, which the jobs allow for.

On Vercel Pro you can instead put all the jobs back in `vercel.json` and delete the workflow file.

| Job | Schedule (UTC) | What it does |
| --- | --- | --- |
| `/api/cron/digests` | hourly | Sends the scheduled report digests that admins set up under Reports |
| `/api/cron/checkin-reminders` | hourly | At 16:00 local time on weekdays, reminds anyone who hasn't checked in (WhatsApp or email) |
| `/api/cron/renewals` | hourly | Renewal reminders 7, 3 and 0 days before expiry (IntaSend payments don't auto-renew), plus seat alerts |
| `/api/cron/payouts` | hourly | Updates M-Pesa payout statuses from IntaSend |
| `/api/cron/ai-briefs` | hourly | Monday 08:00 local: the AI chief-of-staff brief |
| `/api/cron/etims` | hourly | Re-sends invoices and receipts KRA hasn't confirmed yet |
| `/api/cron/calendar` | hourly | Refreshes busy times from connected Google/Outlook calendars |
| `/api/cron/health-snapshot` | daily 00:05 | Records the team-health trend |
| `/api/cron/retention` | daily 01:30 | Deletes data past each workspace's retention setting |

To check the deploy, open `https://app.yourdomain.com/api/health`. It should return status `ok`. If it says `unconfigured`, the Supabase variables are missing; if it says `degraded`, the Supabase URL or anon key is wrong.

## Step 4 — Sentry error alerts

With this step, Sentry emails you within a minute of any crash: a page that fails to load, an API returning 500, or a browser error. Without it, problems only show up when a customer complains.

1. At [sentry.io](https://sentry.io), sign up on the free **Developer** plan. Create a project with platform **Next.js** and alert frequency **Alert me on every new issue**.
2. Copy the **DSN** from Project Settings → Client Keys. Put it in Vercel as `NEXT_PUBLIC_SENTRY_DSN`, then **redeploy**, because the DSN is read when the app is built.
3. Optional, for readable stack traces: go to Settings → Developer Settings → **Organization Tokens** and create a token. Add `SENTRY_AUTH_TOKEN`, `SENTRY_ORG` (your org slug) and `SENTRY_PROJECT` (the project slug) to Vercel. Source maps then upload during each build and are removed from the public site.
4. In **Alerts**, confirm the rule "A new issue is created → send email to" points at you. Optionally add a second rule: "Number of events in an issue is more than 10 in 1 hour".
5. Test it: in the Sentry project, open **Issues** and wait. Then open any page of the app, press F12, and run `setTimeout(() => { throw new Error('sentry test') })` in the console. An issue should appear within a minute.

| Sent | Never sent |
| --- | --- |
| Error message and stack trace | Passwords or request bodies |
| The route that failed (e.g. `/api/meetings/[id]/invite`) | Cookies or auth headers |
| User id and workspace id | Emails or names |
| Browser and OS | One-time codes and tokens in links |

Performance tracing and session replay are off. That keeps you inside the free tier (5,000 errors a month) and avoids recording what people type. Browser errors go through your own domain at `/monitoring`, so ad-blockers don't drop them.

## Step 5 — IntaSend payments

This step makes plan purchases and client invoices take real M-Pesa and card payments. Do the whole thing in **sandbox** first. Live keys go in only after a sandbox payment has worked end to end.

**Sandbox**

1. Create an account at [sandbox.intasend.com](https://sandbox.intasend.com). Under **Settings → API Keys**, copy the publishable key and the secret key.
2. In Vercel, set `INTASEND_PUBLISHABLE_KEY`, `INTASEND_SECRET_KEY` and `INTASEND_TEST_MODE=true`, then redeploy.
3. In IntaSend, go to **Settings → Webhooks → Add webhook** and enter:

| Field | Value |
| --- | --- |
| URL | `https://app.yourdomain.com/api/webhooks/intasend` |
| Challenge | the same random string you put in `INTASEND_WEBHOOK_CHALLENGE` |
| Events | collection (payment) events |

4. Run these three test payments, checking each result in the app:

| Test | How | What you should see |
| --- | --- | --- |
| M-Pesa plan purchase | Settings → Billing → Monthly → **Choose Pro** → enter a sandbox test phone number → **Pay KES…** | Within about 90 seconds the payment row shows complete, the plan changes to Pro, and the receipt PDF downloads |
| Card plan purchase | Settings → Billing → **Choose** any plan → Card, using IntaSend's sandbox test card | You return to OrbitOS and the plan is applied |
| Client invoice | Operations → Finance → **Issue invoice** → **Create & send**, then open the payment link and pay | The invoice turns **Paid** and revenue is recorded |

5. **Foreign currencies:** create a test workspace with currency **EUR** and another with **GBP** (Settings → Organization → Reporting currency), and try a card purchase in each. If IntaSend rejects a currency, remove it from `INTASEND_CARD_CURRENCIES` and redeploy: those workspaces are then charged in USD, and invoices in that currency go out without a payment link.

If the plan never updates, open IntaSend's webhook log. A **401** response means the challenge strings don't match. A **404** means the URL is wrong.

**Going live**

1. Finish KYC at [payment.intasend.com](https://payment.intasend.com) (business registration, ID, KRA PIN and bank or M-Pesa settlement details).
2. Copy the **live** keys and add the same webhook (same URL and challenge) in the live dashboard.
3. In Vercel, swap in the live keys, set `INTASEND_TEST_MODE=false`, then redeploy.
4. Make one small real payment yourself, for example a test client invoice of KES 10, and confirm it lands in your IntaSend wallet.

**Prices** are set in `src/lib/billing/plans.ts`, in cents (KES 4,900 is written `490000`). The current placeholders per month are: Starter KES 4,900 / $39 / €37 / £32, Pro KES 14,900 / $119 / €109 / £95, Enterprise KES 39,900 / $319 / €299 / £259; annual is 10× monthly. Change them there, commit, and redeploy. The pricing page and checkout both read from that file.

## Step 5b — WhatsApp, M-Pesa payouts and the AI chief of staff (optional)

Each of these is off until configured, and the app works without them. Turn them on in this order once Step 5 works.

1. **M-Pesa payouts.** Ask IntaSend to enable **Send Money (B2C)** on your account, then fund the wallet. In sandbox:
   - Draft a payout of two people in Operations → Finance → **M-Pesa payouts**.
   - Approve it as a **second** owner or director who has two-factor on.
   - Confirm each line turns **Paid** and a payroll run appears.

   Details: [`docs/PAYOUTS.md`](PAYOUTS.md).
2. **WhatsApp.** Set up the Meta app and number, then:
   - point the webhook at `https://app.yourdomain.com/api/webhooks/whatsapp` and subscribe to `messages`;
   - submit the four templates (`orbitos_verify_code`, `orbitos_checkin_reminder`, `orbitos_expense_approval`, `orbitos_weekly_brief`) in English, plus Swahili and French if your team uses them;
   - set `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_APP_SECRET` and `WHATSAPP_VERIFY_TOKEN`, then redeploy.

   Template approval can take up to a day. Step by step: [`docs/WHATSAPP.md`](WHATSAPP.md).
3. **AI chief of staff.** Set `ANTHROPIC_API_KEY` (and optionally `ANTHROPIC_MODEL`), then redeploy. As Owner, go to Dashboard → **Chief of staff** → read the note → **Turn on**, then click **Write this week's brief**. The label should say "Written by Claude". Add Anthropic and Meta as subprocessors in your privacy policy. Details: [`docs/AI-CHIEF-OF-STAFF.md`](AI-CHIEF-OF-STAFF.md).

## Step 6 — Smoke test on production

These checks cover the only parts the automated tests could not reach without your real accounts: live Supabase Realtime and Storage, real email, OAuth, and the IntaSend API. Allow about 45 minutes. Stop to fix anything that fails before inviting anyone.

- [ ] **Sign up:** create an account with a real email. The confirmation email arrives, the link opens `/auth/callback`, and you land on onboarding.
- [ ] **Password reset:** request one from `/forgot-password`. The email arrives, and the new password works.
- [ ] **Two-factor:** Profile → Set up two-factor, using an authenticator app. Sign out, sign in, and get the code prompt.
- [ ] **Passkey:** on a laptop with Touch ID or Windows Hello, go to Profile → Add passkey, sign out, then sign in with **Use a passkey**.
- [ ] **Realtime (two browsers):** sign in as yourself in Chrome and as a teammate in a private window. Post in Culture → Channels → #general; the message appears in the other window without a refresh, and the online dot shows both of you.
- [ ] **Storage:** upload an evidence file in Compliance and an avatar in Profile, then reload; both still show. The Vault upload should ask for your TOTP code first.
- [ ] **Invite email:** People → Invite → a second real address. The email arrives, and joining lands that person in your workspace with the role you chose.
- [ ] **Meeting invite:** Scheduling → schedule a meeting with the teammate. They get an email with an `.ics` file that opens in Google Calendar or Outlook.
- [ ] **Calendar sync** (if set up): the five checks in [`docs/CALENDAR.md`](CALENDAR.md) step 3, with one Google and one Microsoft account.
- [ ] **KRA eTIMS** (if set up): the sandbox checks in [`docs/ETIMS.md`](ETIMS.md) step 3, before switching `ETIMS_ENV` to `production`.
- [ ] **Google / Microsoft sign-in:** only if you enabled them in Step 1. Each button should return you signed in.
- [ ] **Payments:** the three sandbox tests from Step 5.
- [ ] **Crons:** after the next full hour, Vercel → Project → **Logs**, filtered on `/api/cron`, shows 200 responses. A 401 means `CRON_SECRET` is missing.
- [ ] **Sentry:** the test error from Step 4 shows as an issue, and the alert email arrived.
- [ ] **Health:** `/api/health` returns status `ok`.
- [ ] **Phone check:** open the app on your phone. Pages fit the screen, and the menu opens.
- [ ] **Languages:** open `/sw` and `/fr`; the public site is in Kiswahili and French. On the sign-in page, pick **Kiswahili**; the page switches. Signed in, Profile → Language → Français; every screen switches, and the choice is kept after signing out and back in. Ask a native Kiswahili and a native French speaker to click through once before launch — the translations are machine-assisted.
- [ ] **Offline:** on your phone, open the app, turn on airplane mode, write a check-in (it says it's saved on the device), turn airplane mode off, and see "Sent 1 check-in…".
- [ ] **WhatsApp** (if set up): link your number in Profile → WhatsApp, send `HELP`, and approve a test expense from the buttons.
- [ ] **Payouts and AI brief** (if set up): the checks in Step 5b.
- [ ] **Foreign visitor view:** open `/pricing` in a browser set to English (United States). Prices show in USD (`$39`), and Profile → Region format → United States shows dates like `Oct 8, 2026`.

## Step 7 — Day one

Start with your own company as the first workspace and a pilot group of 5 to 10 people for a week, then open sign-ups more widely.

1. **Create your workspace.** Sign up at `https://app.yourdomain.com/signup`. In onboarding, enter the company name, a workspace domain, **Billing & reporting currency** = KES, your time zone, and your work-day hours. You become the Owner, and the 14-day trial starts.
2. **Set the organization basics** (Settings → Organization): legal name, the expense approval threshold (expenses above it need a second person to approve), and the average hourly cost that Reports uses to value meeting hours saved.
3. **Lock down sign-in** (Settings → Authentication & identity): turn on **Require two-factor authentication for owners and directors**, and set **Session inactivity timeout** (8 hours is the default).
4. **Add a second Owner.** Invite a co-founder or trusted colleague as Director, then change their role to Owner on the People page. If you lose your phone and your 2FA codes, they can still run billing and settings.
5. **Invite the pilot team** from People → Invite teammates. Give most people **Contributor**, team leads **Director**, and your accountant **Auditor** (read-only).
6. **Seed it with real work:** a few tasks, this week's check-in, and one scheduled meeting, so the dashboard has something to show.
7. **Collect feedback** at the end of the week, then adjust prices in `plans.ts` before inviting outside customers.

**What not to do**

- Never run `supabase/seed.sql` or `supabase db reset --linked` against production.
- Never share the service_role key, or put it in any `NEXT_PUBLIC_` variable.
- Don't switch `INTASEND_TEST_MODE` to `false` until a sandbox payment has worked end to end.
- Don't change the domain after people have registered passkeys.
- Don't edit tables by hand in the Supabase Table Editor to change plans or payments. Billing columns are locked to the server on purpose; use the app or ask a developer.

## Compliance and business items

None of these stop a free pilot. Settle them before the first customer pays you, with your accountant and a lawyer.

| Item | What it means for you | When |
| --- | --- | --- |
| ODPC registration | You hold customers' staff data, so you are a data controller and processor. You must register if turnover is KES 5M+ or you have more than 10 employees; the fee for small firms is KES 4,000, renewed every 2 years ([ODPC guidance](https://www.odpc.go.ke/wp-content/uploads/2024/02/ODPC-Guidance-Note-on-Registration-of-Data-Controllers-and-Data-Processors.pdf)) | Before onboarding outside customers |
| KRA eTIMS | The old KES 5M exemption has been removed, so essentially every business making taxable sales issues eTIMS invoices. Since 1 January 2026, buyers' expense claims are validated against eTIMS ([guide](https://beancount.io/blog/2026/07/22/kenya-kra-etims-income-expense-validation-guide)). OrbitOS's PDF receipts are not eTIMS invoices: issue an eTIMS invoice for each subscription payment, by hand at first | From the first paid subscription |
| VAT | Registration is required once taxable sales pass the threshold (KES 5M in 12 months; confirm with your accountant). After that, prices must include or add 16% VAT, and receipts must show your KRA PIN. This build does not add VAT yet | When you approach the threshold |
| Legal pages | `/legal/privacy` and `/legal/terms` are templates written for this product. Have a Kenyan lawyer review them against the Data Protection Act 2019 and fill in your company name, address and contact | Before outside customers |
| Data processing agreement | Larger customers will ask for one. Have your lawyer prepare a standard DPA | When the first company asks |
| IntaSend KYC | Needed for live payments (Step 5) | Start today; it runs in the background |

Things that can wait until you have paying customers: SAML SSO for enterprise clients, Point-in-Time Recovery backups, a status page, and a security review.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| The app shows a "Supabase is not configured" notice | Supabase variables missing in Vercel | Add the three Supabase variables (Step 3) and redeploy |
| Confirmation or reset emails never arrive | Custom SMTP not set, or the domain isn't verified | Finish Step 2; check Resend → Logs; raise the Supabase email rate limit |
| An email link opens the home page and you aren't signed in | `/auth/callback` missing from Redirect URLs | Add it under Auth → URL Configuration (Step 1) |
| Google or Microsoft sign-in says "redirect_uri mismatch" | The provider has the wrong callback | Use `https://<project-ref>.supabase.co/auth/v1/callback` in Google or Entra |
| "Passkey failed" | `WEBAUTHN_RP_ID` doesn't match the domain in the address bar | Set it to the exact host, e.g. `app.yourdomain.com`, and redeploy |
| A plan payment succeeds but the plan doesn't change | IntaSend webhook missing or wrong challenge | Check the IntaSend webhook log: 401 means the challenge, 404 the URL. After fixing it, ask IntaSend support to resend the webhook |
| "Payments are not configured yet" | IntaSend keys missing | Set both keys and redeploy |
| "Email is not configured", or digests and reminders never send | `RESEND_API_KEY` missing, or the GitHub secrets `ORBITOS_URL` / `CRON_SECRET` missing or wrong | Set the Resend key; check the Actions tab for a failed "Hourly jobs" run (401 = wrong secret) |
| Live chat and presence say "paused" | Realtime blocked by a network or browser extension | Try another network; check Supabase → Realtime for errors |
| A workspace became read-only | The trial or plan expired more than 3 days ago | The Owner pays from Settings → Billing; nothing is deleted |
| Profile says WhatsApp "isn't switched on" | One of the four `WHATSAPP_*` variables is missing | Set all four and redeploy |
| No WhatsApp code arrives | Template `orbitos_verify_code` not approved, or the token expired | Check WhatsApp Manager → Message templates; use a permanent system-user token |
| Replies on WhatsApp do nothing | Webhook not subscribed to `messages`, or wrong app secret (401 in Meta's webhook log) | Re-check Step 5b and `WHATSAPP_APP_SECRET` |
| Payout "Failed — no money moved" | B2C not enabled, or the wallet balance is too low | Ask IntaSend to enable Send Money; top up, then draft again |
| The brief says "Automatic summary" | No `ANTHROPIC_API_KEY`, or the Claude call failed | Set the key; check Vercel logs for `[ai-brief]` |
| An error appears and no one knows why | — | Open Sentry → Issues; the event names the route, user id and stack trace |

For anything not listed: open Sentry first, then Vercel → Logs, then Supabase → Logs → Auth or API, filtered to the time of the problem.
